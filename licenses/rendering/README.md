# Browser rendering provenance

The server has no npm runtime dependencies. These browser assets are committed so deployments do not need npm install. No asset uses a CDN at runtime.

| Asset component | Pinned version | Upstream | License |
| --- | --- | --- | --- |
| Markdown parser | markdown-it 15.0.2 | https://github.com/markdown-it/markdown-it | MIT |
| Math renderer | KaTeX 0.18.10 | https://github.com/KaTeX/KaTeX | MIT |
| Code highlighter | highlight.js 11.12.0 | https://github.com/highlightjs/highlight.js | BSD-3-Clause |
| Output sanitizer | DOMPurify 3.4.16 | https://github.com/cure53/DOMPurify | Apache-2.0 OR MPL-2.0 |
| Diagrams | @mermaid-js/tiny 12.0.0 | https://github.com/mermaid-js/mermaid | MIT, plus embedded dependency notices |
| Build tool | esbuild 0.28.2 | https://github.com/evanw/esbuild | MIT. Not shipped to the browser. |

`package-lock.json` records exact npm tarball URLs and integrity hashes. `scripts/build-renderer.mjs` creates `public/vendor/rich-text.js` from the build-only entry and selected highlighter grammars. It adapts the final global export of the published Tiny bundle to an ES module in `public/vendor/mermaid.js`. The Mermaid implementation is otherwise unchanged. The build preserves embedded license comments. `public/vendor/manifest.json` records generated byte sizes and SHA-256 hashes.

The Tiny archive is a prebundled upstream distribution. Its embedded notices identify Lodash and DOMPurify 3.4.12. Tiny's internal sanitizer is not the application's final output boundary. The application uses the separately pinned DOMPurify 3.4.16 plus a restrictive static SVG policy before insertion. No Tiny callbacks are bound.

This directory contains the full licenses for the bundled parser dependencies and the main libraries. `mermaid-LICENSE` was copied from the official `mermaid@12.0.0` npm archive because the Tiny archive supplies its MIT declaration and bundled notices but no separate license file. `lodash-es-LICENSE` was copied from the official `lodash-es@4.18.1` archive, as identified by Tiny's embedded notice. Apache-2.0 and MPL-2.0 license copies cover the embedded DOMPurify notice as well as the final sanitizer. Keep these reviewed license files when rebuilding assets.

Official API documentation used for integration:

- https://markdown-it.github.io/markdown-it/
- https://mermaid.js.org/config/usage.html
- https://katex.org/docs/options.html
- https://github.com/cure53/DOMPurify

Rebuild with `npm ci --ignore-scripts` and `npm run build:renderer`. See `docs/OPERATIONS.md` for supported syntax, exclusions, security controls, and limits.
